# Production Deployment

The website runs on `syr-prod` as a standalone Next.js container. GitHub Actions
builds one `linux/amd64` image, pushes it to GHCR, and deploys its immutable
digest. The production host never installs pnpm dependencies or builds source.

## Ownership Boundary

The website repository owns only the application containers and their
blue/green lifecycle:

```text
/opt/syr/apps/opensyria/production/website
  bundles/<release-run-attempt>/ # immutable uploaded bundles
  current-bundle -> bundles/<release-run-attempt>
  compose.yaml -> current-bundle/compose.yaml
  bin -> current-bundle/bin
  .infisical.env        # host-only, mode 0600
  .runtime.env          # generated by Infisical export, mode 0600
  .compose.env          # generated image/version state, mode 0600
  .state/               # active and pending rollout state
```

The shared platform owns Cloudflare Tunnel and `infra-nginx`. The app bundle
does not run nginx or cloudflared.

The deployment user has no direct Docker socket access. Every host Docker and
Compose operation goes through `/opt/syr/services/staging/bin/docker`.

Production traffic follows:

```text
Cloudflare -> infra-nginx -> opensyria-production-website-{blue|green}:3000
```

Both website slots join the external `syr-staging-edge` network. That network
name and the `/opt/syr/services/staging` path segment identify the existing
shared host platform; they do not make OpenSyria a staging deployment and must
not be renamed by this app bundle.

Shared nginx selects the active slot through:

```text
/opt/syr/services/staging/infrastructure/nginx/conf.d/includes/opensyria-production-website-active.conf
```

The include contains exactly one upstream assignment. `release.sh` preserves it,
writes replacements atomically, validates nginx, reloads `infra-nginx`, and
restores the prior include when a cutover check fails. Cross-application nginx
changes wait on a shared lock, and private checks retry briefly so a request that
reaches a draining worker during graceful reload does not reject a healthy slot.

## GitHub Production Environment

Required variables:

```text
DEPLOY_HOST
DEPLOY_USER
DEPLOY_ROOT
NEXT_PUBLIC_SITE_URL
NEXT_PUBLIC_DATASETS_API_URL
NEXT_PUBLIC_GOOGLE_TAG_MANAGER_ID
VERIFY_PUBLIC_DEPLOYMENT
```

The deployment values are pinned to `syr-prod`, `mustafa`, and
`/opt/syr/apps/opensyria/production/website`. Production build configuration
must use the following exact public values:

```dotenv
NEXT_PUBLIC_SITE_URL=https://opensyria.org
NEXT_PUBLIC_DATASETS_API_URL=https://api.opensyria.org
NEXT_PUBLIC_GOOGLE_TAG_MANAGER_ID=GT-WPDWW3NR
```

Set `VERIFY_PUBLIC_DEPLOYMENT=false` before Cloudflare is cut over to shared
`infra-nginx`. Set it to `true` after cutover so every deployment verifies the
public health response, release-marked HTML, and RSC response. Manual dispatch
can override this with `required` or `skip`; the inherited value must always be
exactly `true` or `false`.

Required secrets:

```text
TS_OAUTH_CLIENT_ID
TS_AUDIENCE
DEPLOY_SSH_PRIVATE_KEY
DEPLOY_SSH_KNOWN_HOSTS
```

`GITHUB_TOKEN` provides temporary GHCR access. The deployment sends it to
`docker login --password-stdin` and uses a temporary Docker configuration that
is removed before the command exits.

## Host-Side Infisical

Create the private configuration once:

```bash
cd /opt/syr/apps/opensyria/production/website
cp .infisical.env.example .infisical.env
chmod 600 .infisical.env
```

Configure immutable OpenSyria project ID
`5922e0e7-9672-4195-a61f-90db3eb60ce5`, the `production` environment, and the
`/website` secret path. The Universal Auth credentials remain only on
`syr-prod`; they are not GitHub secrets.

During `prepare`, the host runs:

```text
infisical export --projectId=... --env=production --path=/website --format=dotenv
```

The shared platform Universal Auth helper obtains an ephemeral token first. The
result is installed atomically as `.runtime.env` with mode `0600`; no Infisical
CLI login state is persisted. `.infisical.env` is parsed as data, never sourced
as shell code, and rejects duplicate or unknown keys.

The `/website` export must contain exactly these public/runtime values:

```dotenv
NODE_ENV=production
NEXT_TELEMETRY_DISABLED=1
NEXT_PUBLIC_SITE_URL=https://opensyria.org
NEXT_PUBLIC_DATASETS_API_URL=https://api.opensyria.org
NEXT_PUBLIC_GOOGLE_TAG_MANAGER_ID=GT-WPDWW3NR
```

`DEPLOYMENT_VERSION` must be absent because Compose injects the per-release
commit SHA. Preparation fails before starting a slot if this contract drifts.

## Workflow

`.github/workflows/deploy-production.yml` runs after a successful `CI` workflow
for an eligible push to `main`, or by manual dispatch after its own static
validation.

1. Build the Docker `runtime` target once for `linux/amd64`.
2. Push a full-commit tag, provenance, and SBOM to GHCR.
3. Resolve the pushed manifest digest.
4. Join the tailnet and bootstrap the approved `/opt/syr/apps/opensyria`
   directories.
5. Upload a checksummed, versioned `devops/production` bundle and atomically
   activate its `current-bundle` symlink without replacing persistent state.
6. Export runtime configuration from Infisical on the host.
7. Pull the digest and prepare the inactive slot.
8. Require Docker health and an exact commit version from the slot's `/health`.
9. Atomically switch the shared nginx include and run private Host-header smoke
   checks through `infra-nginx`.
10. Optionally verify the public health version, release marker in HTML, and an
    RSC response through `https://opensyria.org` after Cloudflare cutover.
11. Finalize and stop the prior slot only after every enabled check succeeds.
12. Roll back the shared include automatically on switch or verification
    failure.

The workflow runs no tests. CI performs formatting/lint, type checking, and the
dependency audit; a manual deployment repeats those static gates. The Next.js
application is built only once, inside the pushed Docker image.

## Manual Recovery

Inspect state:

```bash
cd /opt/syr/apps/opensyria/production/website
bin/release.sh status
```

If automation is interrupted after switching but before finalization, the prior
slot remains running. Choose one action after inspecting both slots:

```bash
bin/release.sh finalize
bin/release.sh rollback
```

Never edit `.state`, `.compose.env`, or the shared nginx include while a normal
rollout command is running. Deployments are serialized with `flock`.

## Cloudflare Cutover

Before DNS/Tunnel cutover, use the private Host-header checks through
`infra-nginx` and keep public verification disabled. The platform must route
`opensyria.org` to shared `infra-nginx`; it must not point at an app-owned proxy.

After cutover:

1. Enable required public deployment verification.
2. Confirm `/health` returns the expected non-secret commit version with
   `Cache-Control: no-store`.
3. Confirm the automated App Router probe receives `text/x-component`, the
   expected release marker, and an RSC-aware `Vary` response while preserving
   its `_rsc` query key through Cloudflare.
4. Decommission the legacy `/srv/opensyria/website` Compose stack only after the
   shared route has been observed healthy.

## Runtime Notes

- `next.config.ts` uses standalone output, Cache Components, and the commit SHA
  as `deploymentId`.
- Public site, dataset API, and Google tag values are build-time inputs and are
  frozen into the image.
- The image runs as UID/GID 1001, drops all capabilities, uses a read-only root
  filesystem, and permits writes only to bounded tmpfs mounts.
- The two slots do not publish host ports.
- A shared cache is unnecessary because only one website slot receives new
  traffic at a time.
